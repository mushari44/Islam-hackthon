# Sabeeli system audit, night of 3 to 4 October 2026

Audited: `main` at merge commit `84d3991` (after PRs #10 and #11). Fixes are on branch `claude/overnight-audit-sxsdl8`.
Method: the whole test suite and the frontend build, a local server under load, and four parallel code reviews (RAG and core, community and videos, auth and calls, frontend). Every finding below was reproduced or confirmed by reading the code; the ones only read are marked.

**Timing.** Every fix here was committed on 3-4 October before 06:00 UTC (09:00 Riyadh), so it is outside the judging window. Merging before the window makes it part of the disclosed starting version; holding the merge until after 09:00 Riyadh does not change when the commits were written. That is Mushari's call.

**What this run could not measure.** The E5 model (2.2 GB), the Bayyinat data and `.env` are not in git, so this machine ran BM25 only, in sources-only mode, with no model calls. No model latency or answer quality is claimed here; `eval/REPORT.md` remains the source for those.

## 1. Decisions for Mushari

1. **Merge timing** (see above).
2. **Demo reviewer account on the live link.** `reviewer` is an admin with the published password `sabeeli-demo`, seeded by default. Once deployed, anyone can sign in as reviewer, create admins and reset da'i passwords. Eman's area: listed in `tasks/eman.md`. Recommended before any public deploy.
3. **The scripture guard misses short quotations typed by the model** (rule: Quran and hadith text is never generated). Verses under 7 words without brackets («قل هو الله أحد»), hadith under 3 words in quotes, Arabic hadith typed without quotes, and English hadith in quotes all pass if the sentence carries any `[n]` citation. The fix is larger than a night fix (a hadith shingle index like the verse one, plus attribution-phrase checks), so it is proposed as the first RAG task of Day 1. The two related gaps that were small are fixed (section 3).

## 2. Performance

Local run, sources-only, one uvicorn process, SQLite, 2-core container.

| Measure | Before | After |
|---|---|---|
| 20 simultaneous questions + 100 group polls | 202 requests failed with 500 after 30 s (`QueuePool limit of size 5 overflow 10 reached`); polls took 30.7 s median | all 200; questions 0.58 s median, polls 0.7 s median, whole burst 1.0 s |
| 300 simultaneous group polls | pool timeouts | all 200, 193 requests/s, 0.8 s median |
| JS sent to a seeker on first visit | 365 kB uncompressed, no cache header | ~100 kB gzipped (da'i console split into its own 51 kB chunk), cached for a year (`immutable`) |
| Single requests (warm) | `/api/ask` 13-26 ms, groups 5 ms, meetups 7 ms, group poll 3 ms, health 1.5 ms | unchanged |
| Start-up | corpus 0.5 s, BM25 0.7 s, verse matcher 1.1 s, ~300 MB RSS (without E5) | unchanged |

**The main finding: the database pool deadlocked under modest load.** FastAPI runs each request's dependencies and handler on different worker threads, and a session kept its connection between them. With SQLAlchemy's default pool of 15 connections and 40 worker threads, about 20 simultaneous requests could each hold a connection while waiting for a thread, and then every request failed after 30 seconds. With a live model it was worse: `/api/ask` kept its connection open through every model call (2.8 s median, up to 90 s), so about 15 people asking follow-up questions at once would have stopped groups, calls and log-ins. Fixed in `core/db.py` (a fresh SQLite connection per session, a 15 s lock wait) and `rag/routes.py` (the read transaction ends before the model calls; test added).

## 3. Fixed in the pull request

Shared core (review requested from Eman):
- `core/db.py`: the pool deadlock above.
- `core/config.py` and `.env.example`: a `SECRET_KEY` left at `change-me` (the example value) let anyone forge a da'i or admin token. A missing or published value now gets a random key for the run, with a warning. The example file no longer ships a value.
- `core/openrouter.py`: a non-JSON 200 from OpenRouter crashed `/api/ask` with a 500 instead of falling back to sources-only; one unreadable model reply turned off JSON-schema mode for the rest of the process.
- `main.py`: gzip for responses over 1 kB; hashed assets cached for a year.
- `App.jsx`: the da'i console loads on first visit instead of in every seeker's bundle.
- `core/ui.jsx`: Escape closed every stacked sheet at once; now only the top one.
- `pages/Info.jsx`: "Delete my data" reported success even when the request failed (offline, server error) and kept showing the deleted account's name.
- `render.yaml`: the blueprint now runs with the model when `OPENROUTER_API_KEY` is pasted in Render (it forced sources-only and asked for an Anthropic key). Without a key it still runs, sources-only.

RAG (Mushari):
- **Grounding:** a short uncited line ending in ":" before a verse skipped the claim check, so "Your marriage is invalid and you must divorce him, Allah says:" was shown at level D. Intro lines now can't carry a ruling (at level D they are at most 6 words).
- **Scripture guard:** a misquoted verse typed inline kept its altered words after the matching part on screen. The guard now takes the Arabic words joined to the run as well, keeps the verse marker, and drops the altered text.
- **Unrelated verse under a plain request:** «حدثني عن خلق السماوات والأرض» was treated as a misquoted verse and showed 18:50 (Iblis). Request verbs (حدثني، اشرح، أريد ...) are no longer quotes, and a loose phrase from the question that matches several verses below 0.75 is dropped.
- **Photo reading:** malformed OCR output crashed `/api/ask`; OCR text was uncapped (the verse matcher is quadratic); the model's free-text description was shown unchecked. Now normalised and capped; a description carrying a ruling or vowelled text is dropped.
- «أنا مسلم جديد وأريد تعلم الصلاة» was a personal-fatwa case (level D, no content). "I am a Muslim/woman/man" alone no longer counts; it still does next to a ruling word.

Community and videos (Mushari):
- **Meetup capacity could be exceeded and one person could hold several bookings** (8 simultaneous bookings on a 2-seat meetup gave 4 seats; cancelling removed only one of several). Booking, joining, nicknames and the posting rate limit now run under a lock; cancel clears every active booking.
- **Contact-detail redaction was bypassed** with zero-width characters (`0​5​5…`, `evil​.com`, `@​handle`) or dotted phone numbers.
- Related videos stayed on "loading" forever, re-embedding every video on each poll, if embedding failed once; now falls back to words only.
- Video search normalised every title and description on every query (about 1 s of CPU per search on a full list); now once per build.
- The IslamHouse language menu could be fetched by many first visitors at once (~130 calls each); now one at a time.
- A demo meetup was linked to another da'i's group.
- Frontend: Enter twice in a group sent the message twice; an earlier @سبيلي timer hid a later question's "thinking" indicator; leaving the Ask page while an answer was on its way lost the answer; an older chat-list response could overwrite a newer one; photo previews leaked memory.
- `tests/videos/test_related.py` failed to import on a fresh install (`numpy` is optional); it now skips.

Tests: 21 new (`tests/*/test_audit_fixes.py`), 193 passing, 2 skipped; `npm run build` passes. The deadlock, booking-race and connection tests were checked to fail without their fix.

## 4. Found, not fixed (Mushari's areas)

| Severity | Finding | Suggested fix |
|---|---|---|
| High | Short verses/hadith typed by the model pass the guard (section 1, item 3) | Hadith shingle index; attribution-phrase rule; check English quotes ≥5 words |
| Medium | Anonymous chats are deleted only when someone opens Ask (`purge_expired` runs on requests), so 24 h isn't guaranteed if traffic stops | Run all retention purges from a timer started in `lifespan` |
| Medium | E5 can load on the request path if the first question beats the warm-up thread (~15 s wait) (read only) | Non-waiting callers return `None` until loaded |
| Low | Group poll refetches the newest 200 messages (with full bot answers) every 15 s per tab; deletions older than those never reach clients; the da'i view never refreshes deletions | A light `changed_after` endpoint; or move groups to push (already proposed) |
| Low | Demo meetups roll forward only at start-up; a server left running for weeks runs out of them | Roll over from `list_meetups` at most hourly |
| Low | List endpoints (`/api/groups`, `/api/meetups`, `/api/daai/meetups`) and `/api/conversations/{id}` (up to 500 turns with full cards) have no paging | Add `limit`/cursor |
| Low | Videos page fetches twice when the language changes | Reset filters in `pickLang` |
| Low | Hard-coded `ms`, `tokens`, `tok/s` in the Ask trace sheet; `aria-label="main"`/`"tabs"` in `App.jsx`; `aria-selected` on plain buttons in `Info.jsx`; tabs have no arrow-key support; sheets have no focus trap | `t()` keys, `aria-pressed`, a focus trap in `Sheet` |
| Low | The dark-mode icon doesn't follow an OS theme change in "auto" | Subscribe to the `matchMedia` change event |
| Note | The locks above assume one server process (Render runs one). Several workers would need database constraints (a partial unique index on active RSVPs) | When moving to Postgres |

## 6. Checked and fine

- No IDOR found: every seeker route checks the session, every da'i route the assigned da'i; the shared chat needs its own consent.
- Online meetup links reach only the host and people who booked; never the public list or the `.ics` file.
- Videos play only from IslamHouse URLs (YouTube in privacy mode), link back, titles shown as published; related videos need both a meaning and a word match.
- Strict grounding, `_clean_markers`, the fatwa notice at level D and the trace privacy all behave as documented.
- No `dangerouslySetInnerHTML` with data, external links use `noopener`, no RTL-breaking physical CSS, all 451 `t()` keys exist in Arabic and English.
- Path traversal on top-level files is blocked; uploads are capped at 5 MB with a type allow-list.
- Polling pauses in hidden tabs and stops on unmount; WebRTC, sockets and the microphone are released.
